# 렉쳐노트(LectureNote) 로컬 파이프라인 구현 및 시연 계획서 (3차 발표용)

> **작성일:** 2025년  
> **작성자:** 경영전략 팀 프로젝트 9팀 (이병헌, 김도환, 최철원)  
> **현재 단계:** 6주차 — 구현(Implementation) 단계 진입

---

## 1. 프로젝트 개요

본 프로젝트는 대학생의 효율적인 강의 복습을 위해 **음성 녹음(STT), 수업 PDF, 필기 노트**를 결합하여 LLM 기반의 구조화된 노트를 자동 생성하는 서비스입니다.

2차 발표에서 시스템 아키텍처·API 규격·비용 구조 산출을 완료하였으며, 3차 발표에서는 **6주차 마일스톤인 'CLOVA Speech–Gemini 1.5 파이프라인 실제 시연'** 을 목표로 합니다. 현재는 서버 배포 전 **로컬 테스트 환경**에서의 기능 검증에 집중합니다.

---

## 2. 2차 발표 핵심 결정사항 요약 (Carry-over)

3차 발표는 아래 결정사항을 전제로 진행됩니다.

| 항목 | 결정 내용 |
|------|-----------|
| STT 엔진 | **CLOVA Speech API** (알파 단계, NCP 무료 크레딧 활용) |
| LLM | **Gemini 1.5 API** (Google 무료 티어 활용, 1M 토큰 컨텍스트) |
| 비용 이슈 | CLOVA 분당 20원 → 역마진 확인. **알파 단계는 무료 크레딧으로 실비용 0원 운영**, 사업화 시 Whisper/자체 인프라로 전환 예정 |
| 아키텍처 | INPUT(STT + PDF + 필기) → Data Aggregator → Gemini 1.5 → OUTPUT |

> **발표 시 예상 질문 대비:** "역마진 문제는 해결됐나요?" → 알파 단계는 무료 크레딧으로 비용 0원이며, 이후 오픈소스 Whisper 또는 자체 서버 전환으로 원가 구조를 개선할 계획임을 명확히 답변.

## 5. 단계별 구현 프로세스

### 1단계: 환경 설정 및 데이터베이스 스키마 설계

- 프로젝트 루트에 `.env` 파일 생성 → API Key 및 Endpoint 보안 관리
- SQLite 기초 스키마 설계: `Lecture`, `Source`, `Output` 테이블

```sql
-- 예시 스키마
CREATE TABLE Lecture (id, title, subject, created_at);
CREATE TABLE Source (id, lecture_id, type, content, created_at);  -- type: STT/PDF/NOTE
CREATE TABLE Output (id, lecture_id, summary, quiz, created_at);
```

### 2단계: 입력 모듈 구현 (Input)

- **STT 연동:** 로컬 음성 파일(mp3/wav) → CLOVA Speech API 전송 → 텍스트 결과 저장
- **PDF 파싱:** PyMuPDF(fitz)로 수업 PDF 내 텍스트 추출 → Document Parser 구현
- **필기 노트:** 사용자 직접 입력 텍스트 수신 (선택 입력)

### 3단계: 데이터 병합 로직 (Data Aggregator)

- STT 스크립트, PDF 추출 텍스트, 필기 노트를 **단일 컨텍스트**로 병합
- 병합 우선순위: STT(시간 흐름 기준) > PDF(구조 보완) > 필기(강조점 보완)
- 토큰 수 추정 후 Gemini 1.5 API 호출 전 전처리 수행

### 4단계: Gemini 1.5 연동 및 프롬프트 튜닝

- 병합된 텍스트를 Gemini 1.5 API에 전달하여 아래 두 가지 결과물 생성

**목표 출력 형식 (프롬프트 설계 기준):**

```
[구조화 요약 노트]
## 1. 오늘 강의 핵심 주제
## 2. 주요 개념 정리
  - 개념 A: 설명
  - 개념 B: 설명
## 3. 교수님 강조 포인트
## 4. 보충 자료 연계

[예상 문제]
Q1. ...
Q2. ...
Q3. ...
```

- 1M 토큰 컨텍스트를 활용하여 1~2시간 강의 전체를 단일 API 호출로 처리
- 프롬프트 버전 관리를 통해 출력 품질 반복 개선 (v1 → v2 비교 시연 포함)

### 5단계: 결과 출력 및 검증 (Output)

- 생성된 노트를 과목별 SQLite DB에 저장
- FastAPI 엔드포인트를 통해 결과물 JSON 응답 확인
- 콘솔 로그 및 API 응답으로 파이프라인 전 구간 흐름 시각화

## 6. 6주차 시연 시나리오 (발표용 상세 스크립트)

발표장에서 실제로 보여줄 순서를 아래와 같이 구성합니다.

**준비물**
- 테스트용 강의 녹음 파일: 약 5분 분량 (실제 강의 또는 TTS 생성본)
- 관련 수업 PDF 1개
- 간단한 필기 노트 텍스트 1개

**시연 순서**

1. **[환경 확인]** 로컬 FastAPI 서버 구동 → 터미널 출력 화면 공유
2. **[INPUT 시연]** API 호출로 음성 파일 + PDF + 필기 노트 3개 소스 업로드
3. **[Data Aggregator 확인]** 병합 로그 출력 → 세 소스가 하나의 컨텍스트로 합쳐지는 과정 확인
4. **[Gemini API 호출]** 병합된 텍스트 → Gemini 1.5 전송 → 응답 대기
5. **[OUTPUT 확인]** 구조화된 요약 노트 + 예상 문제 3~5개 출력 결과 화면 공유
6. **[DB 저장 확인]** SQLite에 결과물이 과목별로 저장된 것 확인

> **예상 소요 시간:** 시연 약 3~5분 (라이브 또는 사전 녹화본 병행 준비 권장)
