# [AI 코딩 어시스턴트 전달용 프롬프트]

너는 Python과 FastAPI를 활용하여 백엔드 파이프라인을 구축하는 수석 개발자야.
현재 내 프로젝트 디렉토리 하위의 `project_plan` 폴더에는 이번 프로젝트(LectureNote)의 핵심 기획 및 설계 문서 4개가 저장되어 있어.

1. `3차발표_대비_기획.MD`: 전체 아키텍처 및 6주차 로컬 시연 목표
2. `syllabus_analysis.md`: `/api/create-step0` 엔드포인트에서 사용할 강의계획서 분석용 LLM 시스템 프롬프트
3. `make_note.md`: `/api/generate-note` 엔드포인트에서 사용할 노트 생성용 LLM 시스템 프롬프트
4. `백엔드_구현_가이드.md`: 디렉토리 구조 및 단계별 구현 목표

이 문서들을 모두 읽고 완벽히 숙지한 후, 아래의 지시사항에 따라 백엔드 애플리케이션 코드를 작성해 줘. 한 번에 모든 코드를 쏟아내어 잘리는 것을 방지하기 위해, 내가 명시한 **순서대로 하나씩** 코드를 제공하고 다음 단계로 넘어가기 전 나의 승인을 기다려.

---

## [기술 스택 및 공통 제약 사항]

* Framework: FastAPI (Python 3.10+)
* DB/ORM: SQLite, SQLAlchemy
* Libraries: `pymupdf` (PDF 파싱), `google-generativeai` (Gemini API), `requests`, `python-dotenv`
* 모든 코드는 즉시 실행 가능해야 하며, `pass`나 `TODO` 같은 생략 없이 완성된 형태로 작성할 것.
* 코드에 대한 설명은 주석으로 남기고, 불필요한 부연 설명은 최소화할 것.

---

## [작업 진행 순서]

### Step 1: 환경 설정 및 DB 구조 (`database.py`, `models.py`)

* `project_plan/백엔드_구현_가이드.md`의 1단계를 참고하여 작성해 줘.
* `database.py`: SQLite 연동을 위한 엔진, 세션 팩토리, 베이스 클래스 정의.
* `models.py`: `Lecture`(step0_analysis 컬럼 포함), `Source`, `Output` 테이블 정의.
* 작성이 완료되면 다음 단계로 넘어가도 되는지 물어봐.

### Step 2: 개별 입력 소스 처리 (`services/pdf_parser.py`, `services/stt_service.py`)

* `pdf_parser.py`: `fitz`를 사용해 PDF 파일 바이트 스트림에서 텍스트를 추출하는 `extract_text_from_pdf(file_bytes: bytes) -> str` 작성.
* `stt_service.py`: 오디오 바이트를 받아 하드코딩된 가짜 STT 텍스트를 반환하는 Mock 함수 `process_audio_to_text(audio_bytes: bytes) -> str`로 작성할 것. (실제 CLOVA API 호출 코드는 주석으로 포함)
* 작성이 완료되면 다음 단계로 넘어가도 되는지 물어봐.

### Step 3: 데이터 병합 로직 (`services/aggregator.py`)

* `project_plan/make_note.md`의 워크플로우에 맞춰 Step 0, PDF 텍스트, STT 텍스트, 필기 노트를 구분자(태그)와 함께 하나의 문자열로 병합하는 `aggregate_sources(step0, pdf_text, stt_text, note_text) -> str` 함수를 작성해 줘.
* 작성이 완료되면 다음 단계로 넘어가도 되는지 물어봐.

### Step 4: LLM 연동 (`services/llm_service.py`)

* `google.generativeai`를 활용하여 Gemini 1.5 Pro 모델(모델 ID: `gemini-1.5-pro-latest`)을 호출하는 아래 두 가지 함수를 작성해 줘.
* `analyze_syllabus(syllabus_text: str) -> str`:
  * `project_plan/syllabus_analysis.md` 파일을 런타임에 직접 읽어(`open()`) System Instruction으로 사용.
  * `syllabus_text`를 사용자 프롬프트로 전달하여 Step 0 분석 결과(마크다운)를 반환.
* `generate_lecture_note(aggregated_text: str) -> str`:
  * `project_plan/make_note.md` 파일을 런타임에 직접 읽어(`open()`) System Instruction으로 사용.
  * `aggregated_text`를 사용자 프롬프트로 전달하여 마크다운 노트를 반환.
* 작성이 완료되면 다음 단계로 넘어가도 되는지 물어봐.

### Step 5: API 엔드포인트 통합 (`main.py`)

* FastAPI 앱을 초기화하고, 앱 시작 시 DB 테이블을 자동 생성하도록 설정.
* `project_plan/백엔드_구현_가이드.md`의 5단계를 참고하여 아래 두 엔드포인트를 작성해 줘.

**`POST /api/create-step0`** (강의계획서 분석 및 Step 0 저장)
1. `title`, `subject`(Form), `syllabus_file`(UploadFile)을 수신.
2. `Lecture` 레코드를 먼저 생성하여 `lecture_id` 확보.
3. `syllabus_file`에서 텍스트 추출 (PDF이면 `pdf_parser` 활용, 텍스트 파일이면 직접 decode).
4. `llm_service.analyze_syllabus()`로 Step 0 분석 결과 생성.
5. 해당 `Lecture.step0_analysis` 컬럼에 저장.
6. `lecture_id`와 분석 결과를 JSON으로 반환.

**`POST /api/generate-note`** (주차별 노트 생성)
1. `lecture_id`(Form), `pdf_file`(UploadFile, 선택), `audio_file`(UploadFile, 선택), `note_text`(Form, 선택)를 수신.
2. `lecture_id`로 DB에서 `Lecture` 레코드를 조회하여 `step0_analysis` 확보. (없으면 404 반환)
3. `pdf_parser`와 `stt_service`로 텍스트 추출.
4. `aggregator`로 step0 + pdf + stt + note 병합.
5. `llm_service.generate_lecture_note()`로 요약 노트 생성.
6. 원본 소스를 `Source` 테이블에 type별로 각각 저장.
7. 생성된 노트를 `Output` 테이블에 저장.
8. 생성된 마크다운 결과를 JSON으로 반환.

자, 이제 문서를 확인하고 **Step 1**의 코드 작성을 시작해.
