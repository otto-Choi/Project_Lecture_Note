## SLIDE 5 — 백엔드 완성 현황

**제목:** 3개 API 엔드포인트, 실제 동작 확인 완료

**구현된 기능:**

| API | 기능 | 입력 | 출력 |
|-----|------|------|------|
| `POST /api/create-step0` | 강의계획서 분석 | 강의명 + PDF | 강의 로드맵 (Step 0) |
| `POST /api/generate-note` | 통합 노트 생성 | 음성 + PDF + 필기 | 5섹션 구조화 노트 |
| `GET /api/download-note/{id}` | 노트 다운로드 | 노트 ID | HTML 파일 |

**기술 스택:**
```
Python 3.13  ·  FastAPI  ·  SQLite + SQLAlchemy  
PyMuPDF  ·  google-genai SDK  ·  python-dotenv
```

> **[발표자 멘트]**
> 현재 백엔드에는 세 개의 API 엔드포인트가 구현되어 있습니다.
> 첫 번째는 강의계획서를 업로드하면 LLM이 전체 커리큘럼을 분석해서 이번 수업이 전체 강의에서 어떤 위치인지 파악하는 Step 0 분석 기능입니다.
> 두 번째는 실제 수업 날, 음성 파일과 수업 자료 PDF, 그리고 개인 필기를 올리면 통합 요약 노트를 생성해주는 핵심 기능입니다.
> 세 번째는 생성된 노트를 HTML 파일로 다운로드할 수 있는 기능으로, 브라우저에서 열고 인쇄하면 PDF로 저장됩니다.
> 세 기능 모두 실제 음성 파일과 PDF로 테스트해서 정상 동작을 확인했습니다.

## SLIDE 9 — STT 전략 변경: CLOVA → Gemini

**제목:** 2차 발표 이후 변경된 핵심 설계 결정

**변경 전후 비교:**

| 항목 | 2차 발표 계획 | 3차 발표 현재 |
|------|--------------|--------------|
| STT 엔진 | CLOVA Speech API | **Gemini 멀티모달** |
| STT 비용 | 분당 ₩20 (역마진 핵심 원인) | LLM과 통합 과금 |
| 외부 의존성 | CLOVA + Gemini (2개 API) | Gemini 1개 |
| 한국어 정확도 | 90%+ (CLOVA 강점) | Gemini 2.5-flash 수준 |

**변경 이유 (3가지):**

1. **비용 합리성**
   - 2차 발표에서 STT가 전체 비용의 90%라는 역마진 문제를 이미 확인
   - CLOVA 무료 티어 소진 시 즉시 서비스 중단 위험 — 개발 중 실제 발생
   - Gemini는 LLM과 동일 API 키, 단일 청구 → STT 별도 비용 구조 제거

2. **아키텍처 단순화**
   - 외부 STT API 제거 → 장애 지점 감소, 유지보수 단순화
   - 음성 파일을 그대로 Gemini에 전달 (멀티모달) → 변환 단계 없음

3. **향후 오픈소스 전환 준비**
   - 현재: Gemini STT (프로토타입, 빠른 통합 목적)
   - 사업화 단계: OpenAI Whisper (오픈소스) 자체 서버 배포
     - STT 비용 완전 제거 가능
     - 음성 데이터가 외부 서버로 전송되지 않음 (보안/개인정보)
     - AWS EC2 자체 배포 시 운영비 월 수천 원 수준
   - 이 경로는 2차 발표에서 제시한 "Whisper 전환" 계획과 동일 방향

> **[발표자 멘트]**
> 2차 발표에서 저희는 STT 비용이 전체 원가의 90%를 차지해서 역마진 구조라는 문제를 솔직히 말씀드렸고, 해결 방안으로 Whisper 전환을 언급했습니다.
> 이번에 그 결정을 한 단계 앞당겼습니다. CLOVA 무료 티어가 개발 중에 소진되면서 실제로 서비스가 멈추는 상황이 발생했고, 이를 계기로 Gemini 멀티모달 STT로 전환했습니다.
> Gemini는 음성 파일을 바로 이해할 수 있어서 별도 STT 변환 없이 하나의 API 호출로 처리됩니다. 비용 구조도 LLM과 통합되어 단순해졌습니다.
> 장기적으로는 Whisper 오픈소스를 자체 서버에 배포해서 STT 비용을 완전히 없앨 계획입니다. 이렇게 되면 2차 발표에서 제기한 역마진 문제도 구조적으로 해결됩니다.

## SLIDE 10 — 차별화 전략: 왜 우리 서비스인가

**제목:** "Gemini 직접 쓰면 되지 않나?" — 저희의 답

**질문:** 모든 기능을 Gemini API로 구현하면, 사용자가 직접 Gemini를 쓰면 되는 것 아닌가?

**렉처노트만의 4가지 차별화:**

### 1. 원클릭 녹음 통합 (예정)
```
현재 흐름:  수업 중 별도 앱 녹음 → 파일 저장 → 업로드 → 기다림
렉처노트:   앱 열기 → 녹음 시작 → 수업 끝나면 '생성' 버튼 → 완료
```
- 수업 중 추가 행동 없이 원클릭으로 노트 생성
- 녹음 파일 관리 필요 없음

### 2. 강의계획서 기반 맥락 자동 주입
```
Gemini 직접 사용:  매번 "이 수업은 OO학과 OO 강의인데요..." 프롬프트 작성 필요
렉처노트:          학기 초 1회 업로드 → 이후 매주 자동으로 맥락 포함
```
- "이 개념이 기말고사에서 얼마나 중요한지"를 강의계획서 기반으로 자동 판단
- 일반 사용자가 이런 수준의 프롬프트를 직접 설계하기 어려움

### 3. 데이터 프라이버시 경로 제공
```
현재:  사용자 음성 → Gemini 서버 (Google 처리)
목표:  사용자 음성 → 렉처노트 서버 → Whisper (자체) → Gemini는 텍스트만 수신
```
- 강의 음성(교수 목소리, 수업 내용)이 Google 서버로 직접 전송되지 않음
- 보안에 민감한 대학, 기업 교육 시장 공략 가능

### 4. 한국 대학 시험 구조 최적화
```
일반 AI 요약:   내용 정리
렉처노트 노트:  [교수님 힌트] + [중요도 별점] + [셀프 시험 문제]
```
- 한국 대학 시험 방식(서술형/객관식 혼합)에 맞춘 전용 노트 포맷
- 교수님이 수업 중 강조한 부분을 STT로 포착해서 시험 출제 포인트로 분류

> **[발표자 멘트]**
> 사실 이 질문은 저희도 스스로에게 던진 질문입니다. 다 Gemini면 왜 굳이 저희 서비스를 쓰나?
> 첫 번째는 사용성입니다. 수업 중에 별도 앱 열고, 파일 저장하고, 업로드하는 과정을 거치는 것과, 앱 하나 켜서 녹음 시작 버튼 누르는 것은 완전히 다른 경험입니다. 특히 수업 집중도를 유지하면서 노트를 남기려는 학생에게는 이 차이가 큽니다.
> 두 번째는 강의계획서 기반 맥락입니다. Gemini에게 강의 내용을 붙여 넣어도, 그게 전체 강의에서 몇 번째 챕터이고 어느 부분이 기말고사에 나올 가능성이 높은지는 직접 설명해줘야 합니다. 저희는 이걸 강의계획서를 읽어서 자동으로 처리합니다.
> 세 번째는 프라이버시입니다. Whisper를 자체 서버에 배포하면, 강의 음성이 Google 서버로 가지 않고 저희 서버에서만 처리됩니다. 학교 강의는 저작권이나 보안 문제가 있을 수 있기 때문에 이 부분은 기관 영업에서 중요한 포인트가 됩니다.
> 네 번째는 포맷입니다. 단순 요약이 아니라, 교수님 강조 포인트를 별도로 분류하고 시험에 나올 법한 문제를 함께 생성해주는 것은 일반 AI 툴에서는 바로 얻을 수 없는 결과물입니다.

## 예상 질문 & 답변 준비

**Q1. STT를 Gemini로 바꾸면 정확도가 CLOVA보다 떨어지지 않나요?**
> A. Gemini 2.5-flash는 멀티모달 모델로 음성 인식 성능이 상당히 높습니다. 실제 조직행동론 강의 음성으로 테스트한 결과 한국어 받아쓰기 품질이 충분한 수준으로 확인됐습니다. 다만 CLOVA의 90%+ 정확도와 직접 비교 테스트는 향후 알파 단계에서 진행할 예정입니다.

**Q2. 역마진 문제는 아직 해결 안 된 것 아닌가요?**
> A. 맞습니다. 현재 단계에서는 무료 API 크레딧으로 운영하고 있어 실비용이 0원입니다. 사업화 단계에서는 Whisper 오픈소스를 자체 서버에 배포해서 STT 비용을 제거하는 계획을 갖고 있습니다. AWS EC2 서버 비용을 감안해도 현재 CLOVA 기준 역마진보다 훨씬 개선된 구조가 됩니다.

**Q3. 결국 Gemini 없이는 작동이 안 되는 거 아닌가요?**
> A. 현재 프로토타입은 그렇습니다. 장기적으로는 STT는 Whisper(자체), LLM은 다른 오픈소스 모델로 대체 가능하도록 아키텍처를 설계했습니다. Gemini 의존성을 줄이는 것이 10주차 이후 과제 중 하나입니다.

**Q4. 프론트엔드는 언제 만드나요?**
> A. 8주차 알파 빌드가 목표입니다. 백엔드 API가 완성된 상태이기 때문에 프론트엔드는 API를 호출하는 UI를 붙이는 작업입니다. 웹 기반 React 또는 간단한 HTML 페이지로 시작할 예정입니다.
