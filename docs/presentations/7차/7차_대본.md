### 슬라이드 2 — 프로젝트 타임라인 `(1:30)`

### 슬라이드 3 — 문제 정의 + SDLC `(1:30)`

저희가 해결하려 했던 문제는 간단합니다.

대학생이라면 누구나 겪는 세 가지 상황이 있습니다.
빠른 강의 속도 때문에 필기와 집중을 동시에 하기가 어렵고,
녹음 파일과 PPT, 필기가 뿔뿔이 흩어져 있어 통합 정리가 불가능하고,
구조화된 복습 노트가 없어서 시험 때마다 처음부터 다시 정리해야 합니다.

저희 솔루션은 한 줄로 요약하면,
"STT와 PDF와 필기를 입력으로 받아 LLM이 구조화 노트를 만든다"입니다.

개발 방법론으로는 소프트웨어 공학의 SDLC 표준 모델을 따랐습니다.
요구분석 → 설계 → 구현 → 테스트 → 배포·운영 다섯 단계를 순서대로 진행해왔고,
현재는 배포·운영 단계에 있습니다.

### 슬라이드 4 — 데이터 파이프라인 `(2:00)`

시스템이 어떻게 동작하는지 파이프라인 구조로 설명드리겠습니다.

사용 흐름은 크게 두 가지로 나뉩니다.

첫 번째는 강의 등록으로, 학기 초에 한 번만 하면 됩니다.
강의계획서 PDF를 업로드하면 Gemini가 분석해서 커리큘럼 구조, 즉 Step 0 로드맵을 자동으로 추출하고 DB에 저장합니다.

두 번째는 매주 반복하는 노트 생성입니다.
수업 후에 녹음 파일, 수업자료 PDF, 그리고 선택적으로 개인 필기를 업로드합니다.
Gemini가 음성을 텍스트로 변환하고, PDF를 파싱하고, 앞서 저장해둔 강의 맥락과 함께
Data Aggregator가 모든 정보를 통합합니다.
그러면 Gemini LLM이 5개 섹션으로 구성된 구조화 노트를 생성합니다.

5개 섹션은 개요, 통합 노트, 교수님 힌트, 핵심 암기 목록, 그리고 예상 시험 문제입니다.

최종 결과물은 DB에 저장되고, PDF나 HTML 파일로도 다운로드할 수 있습니다.

핵심 포인트는, 처음 강의계획서를 한 번 등록해두면 이후 매주 노트를 만들 때 교수님의 강의 의도와 출제 경향이 자동으로 반영된다는 점입니다.

### 슬라이드 5 — STT 전략 변경 `(1:30)`

개발 중에 바뀐 중요한 설계 결정을 하나 공유드립니다.

원래 2차 발표 때는 네이버 CLOVA를 STT에 쓰기로 했었는데,
개발 도중 CLOVA 무료 티어가 소진되면서 실제 서비스가 중단되는 상황이 생겼습니다.

이 시점에 구조를 재검토했고, 결국 Gemini의 멀티모달 기능으로 전환했습니다.
음성 파일을 별도 변환 없이 Gemini에 직접 전달하는 방식입니다.

장점이 세 가지입니다.
첫 번째는 비용입니다. LLM과 동일한 API 키를 쓰기 때문에 STT 별도 비용 구조가 사라집니다.
두 번째는 아키텍처 단순화입니다. 외부 STT API가 제거되니 장애 지점이 줄어들고 유지보수가 훨씬 편해졌습니다.
세 번째는 향후 전환 가능성입니다. 현재는 프로토타입 단계라 Gemini를 쓰지만, 사업화 단계에서는 Whisper 자체 서버로 전환해서 음성 데이터가 외부로 나가지 않도록 할 계획입니다.

### 슬라이드 6 — 사용자 피드백 `(2:00)`

시연 영상을 보시기 전에, 이 영상에 담긴 결과물이 만들어지기까지의 과정을 먼저 보여드리겠습니다.

저희는 5차 베타 빌드를 외부 사용자 5명에게 직접 써보게 하고 인터뷰를 진행했습니다.

결과를 표로 정리해드리면,
먼저 긍정적인 반응입니다. 세 명이 하단 탭 구조가 직관적이라고 했고, 두 명은 예상 문제 자동 생성이 가장 유용하다고 답했습니다. 대학 수업은 문제집이 없기 때문에 셀프 점검 도구로서 가치가 크다는 이야기였습니다. 이 두 강점은 그대로 유지했습니다.

개선 사항은 세 가지가 나왔습니다.
"강의 등록"과 "노트 생성"의 차이가 처음엔 헷갈린다는 의견에는, Step 0 배지와 "학기 초 1회" 라벨을 추가해서 반영 완료했습니다.
다크모드에서 색 대비가 약하다는 의견에는 전체 배경 CSS 변수를 재정의해서 반영했습니다.
수업자료와 녹음 파일을 복수로 올리고 싶다는 의견에는 백엔드 list 입력 지원과 프론트 UI 추가로 반영했습니다.

이렇게 5건의 피드백을 전원 반영한 뒤 만들어진 결과물이 지금 보실 최종 빌드입니다.

### 슬라이드 9 — Gemini 직접 쓰면 되지 않나? `(1:30)`

시연을 보시고 나면 이런 질문이 나올 수 있습니다.
"그냥 Gemini 직접 쓰면 되지 않나?"

저희의 답은 네 가지입니다.

첫 번째, 원클릭 녹음 통합입니다.
지금은 녹음 파일을 따로 저장해서 업로드하지만, 로드맵에는 앱 안에서 바로 녹음하고 수업이 끝나면 버튼 하나로 노트가 만들어지는 흐름을 목표로 합니다.

두 번째, 강의계획서 기반 맥락 자동 주입입니다.
Gemini를 직접 쓰면 매번 프롬프트에 강의 배경을 직접 설명해야 합니다.
저희 서비스는 학기 초에 한 번 강의계획서를 올리면 이후 매주 자동으로 그 맥락이 포함됩니다.

세 번째, 데이터 프라이버시 경로입니다.
현재는 Gemini로 STT를 처리하지만, Phase 2 로드맵에서는 음성이 저희 서버에서 Whisper로 처리되고 Gemini에는 텍스트만 전달됩니다. 음성 데이터가 외부로 나가지 않는 구조입니다.

네 번째, 한국 대학 시험 구조 최적화입니다.
일반 AI 요약은 내용 정리에 그치지만, 저희 노트는 교수님 힌트, 중요도 별점, 그리고 셀프 시험 문제까지 포함합니다.

### 슬라이드 10 — B2B 확장 · 수익화 `(1:30)`

저희 파이프라인의 본질은 강의 요약이 아닙니다.
"비정형 멀티모달 입력을 구조화 출력으로 변환하는 AI 워크플로우"입니다.

이 구조의 핵심은 Step 0 컨텍스트만 교체하면 도메인이 바뀐다는 점입니다.
강의계획서 대신 안건 목록을 넣으면 회의 요약 도구가 되고,
검토 체크리스트를 넣으면 법무 리뷰 도구가 됩니다.
온보딩 가이드를 넣으면 사내 교육 정리 도구로 쓸 수 있습니다.
코드 변경 없이 컨텍스트 문서 교체만으로 도메인 전환이 가능합니다.

수익화 구조는 프리미엄 모델로 구성했습니다.
무료 플랜은 강의 3개, 월 10회 노트 생성으로 서비스를 경험할 수 있고,
Pro 플랜은 월 9,900원으로 무제한 사용에 다중 파일 업로드와 노트 공유가 추가됩니다.
Team 플랜은 월 29,900원으로 팀 워크스페이스와 관리자 대시보드를 제공합니다.

### 슬라이드 12 — 기술 로드맵 `(0:30)`

현재 스택은 몰라서가 아닌, 검증 전 복잡도 최소화를 위한 의도적 선택입니다.

Phase 3에서는 Celery와 Redis 비동기 큐, 전용 STT 서버로 동시 사용자 수십 명 이상을 처리합니다.
